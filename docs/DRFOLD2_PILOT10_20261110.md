## Observed completion

Each of the ten target folders contains `model_1.pdb`, `inference.log`, and `complete.json`. Each completion record includes the target name, upstream commit, input and native SHA-256, output PDB SHA-256, runtime, device, and basic PDB sanity-check summary. The Colab batch printed `Verified complete: 10 / 10`; the folder contents were subsequently checked from Google Drive.

The summed recorded per-target inference runtimes are **9,349.111 s (approximately 2 h 36 min)**, excluding installation, downloads, and other notebook overhead. These per-target wall times are not directly comparable with previous NuFold published/pilot timings without controlling preprocessing and resource measurement.

## Installation incident and recovery

The first Colab installation attempt stopped after the weights archive was downloaded and extracted. Arena compilation had not succeeded because `clang++` was unavailable. Installing the Clang package and running `make Arena` recovered the setup without repeating the weight download. The archived Colab notebook now checks for Clang **before** invoking the upstream installer; it also tries Arena-only compilation if weight directories already exist.

## Recovery behavior

Outputs are written under a run-ID directory on Google Drive. When `complete.json` and the expected PDB hash validate, re-execution skips that target. A failed or interrupted target with an incomplete result directory stops for manual inspection; the notebook does **not** silently overwrite it.

## Interpretation and next step

This is evidence of runnable **single-sequence FASTA inference**, not proof of structural accuracy or superiority over NuFold. The native reference chains include incomplete coordinates (for example, only 13 of 36 residues mapped for `8ubd_H`); direct full-length coordinate RMSD against those incomplete native coordinates would be invalid.

Next: apply the established NuFold native-residue mapping and a common US-align configuration to DRfold2 predictions; compute per-target TM-score, RMSD, and alignment coverage; confirm the exact metric/atom policies before comparing against NuFold. lDDT and INF require their own standardized definitions and tooling.

No large PDB structures, checkpoints, or private datasets were added to GitHub.
